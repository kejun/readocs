# 墨水屏刷新基线（P0）

日期：2026-10-24  
固件：readocs-0.2.2  
硬件：M5Stack PaperDIY / ESP32-S3  
驱动：M5GFX `Panel_EPD` + `Bus_EPD`，8 位并口  
M5GFX：`02107b828acb3eb782fccd747863638d64c876d7`  
M5Unified：`2fe93c0c64f12f916e73a0605c86bf1241c06a6b`  
ESP-IDF：v5.5.5

## 当前整屏刷新的原因

所有 UI 绘制都会经过：

```text
draw_* -> begin() -> fillScreen(TFT_WHITE)
       -> finish() -> setEpdMode(epd_quality)
       -> display() -> waitDisplay()
```

`begin()` 的 `fillScreen` 把整个 540×960 缓冲标记为已修改，`Panel_EPD::display()` 使用累计的 `_range_mod`，因此当前每次 UI 更新都是整屏质量波形刷新。

实测一次 UI 整屏刷新：

```text
readocs: epd ui mode=quality time_ms=2283
```

## 驱动能力

驱动本身支持矩形区域刷新：

- `Panel_EPD::display(x, y, w, h)`
- `Panel_EPD::_update_transferred_rect()` 维护 `_range_mod`
- `setAutoDisplay(false)` 下，绘制只累计脏区，`display()` 提交该区域

限制：

- 横向起始坐标会向下对齐到偶数像素；
- 宽度会扩展到包含对齐后的像素对；
- 不是“调用接口就必然只刷局部的假接口”，实测局刷区域耗时明显低于整屏。

## 模式对比

LUT 步数来自 `Panel_EPD.cpp`：

| 模式 | LUT 步数 | 灰度 |
|---|---:|---|
| `quality` | 20 | 16 级 |
| `text` | 13 | 16 级，带擦除阶段 |
| `fast` | 9 | 1 位 Bayer 阈值 |
| `fastest` | 6 | 1 位 Bayer 阈值 |

`epd_probe` 实测（`display()` + `waitDisplay()`，不含绘制时间）：

| 模式 | 局刷 476×240 | 整屏 540×960 |
|---|---:|---:|
| quality | 1530 / 1530 ms | 2284 / 2286 ms |
| text | 1530 / 1401 ms | 2228 / 1752 ms |
| fast | 464 / 408 ms | 692 / 439 ms |
| fastest | 341 / 300 ms | 516 / 330 ms |

局刷区域小，耗时确实更低，但质量模式固定开销很高，不能假设耗时与面积线性。

## 可重复测试命令

串口发送：

```json
{"cmd":"epd_probe","mode":0,"area":"both","count":2}
```

- `mode`：0 全部，1 quality，2 text，3 fast，4 fastest
- `area`：`both` / `partial` / `full`
- `count`：每个组合重复次数，1–5

探针区域为 `x=32, y=120, w=476, h=240`，绘制 24px 文字和移动黑块；每条结果输出：

```text
readocs: epd probe mode=... area=... iter=... time_ms=...
```

## P0 结论

1. 当前明显闪屏来自 `begin()` 的整屏 `fillScreen`，不是驱动缺少局刷能力。
2. `epd_text` 是整页文字 UI 的优先候选：保留 16 级灰度，耗时略低于 quality。
3. `fast` / `fastest` 快 3–6 倍，但只有 1 位灰度，必须单独验证残影和文字清晰度，不能直接作为所有界面的默认。
4. 菜单和列表应做小区域局刷；首次进入、页面切换和周期性残影清理再用高质量整屏刷新。
5. 视觉上的闪屏、清晰度和残影仍需要实机目视确认；当前记录的是可重复的时间基线。

## P1 实现（2026-10-24）

已把文字界面默认整屏模式改为 `epd_text`，并为菜单和文章列表增加局刷：

- 菜单换选项只重画旧选中行和新选中行，使用 `epd_fast`；内容、标题和选中项都未变化时直接跳过刷新。
- 文章列表换选中项只重画旧/新行；翻页或目录内容变化才整屏刷新。
- 主循环原有按键队列会把连续 A 合并为一次绘制。
- 整屏刷新、探针和页面切换会使菜单/列表局刷缓存失效，避免局部状态错位。

实测：

| 场景 | 耗时 |
|---|---:|
| 整屏 `epd_text`（稳定交替菜单/列表） | 1637–1638 ms |
| 菜单单步局刷 | 436–477 ms |
| 列表单步局刷 | 约 449 ms |
| 三次 A 合并后的菜单局刷 | 477 ms |
| 三次 A 合并后的列表局刷 | 1021 ms |
| 连续 3 次 A 的刷新次数 | 1 次 |
| 7 次 A 回到原选中项的刷新次数 | 0 次 |

整屏 `epd_text` 在交替菜单/列表时稳定为约 1.64 s，优于原 `quality` 的约 2.28 s。会话中同时有同步或旧局刷时，个别整屏刷新出现 1.9–3.1 s 的波动，P2 需要在真实负载下继续测量。

局刷使用 `epd_fast`（1 位阈值），文字清晰度和残影还需要实机目视确认；P2 将统计连续局刷次数并设置质量清理阈值。详细数据见 `p1.json` 和 `p1.log`。

## P2 实现（2026-10-24）

已加入分级刷新和残影清理：

- 连续局刷计数，默认阈值 20 次。
- 计数器达到阈值后，下一次完整屏幕切换自动使用 `epd_quality`。
- 若没有完整切换，空闲 1 秒后对当前界面执行一次质量刷新。
- 网络同步期间、配网期间不打断；快速连续按键期间不插入质量刷新，等交互停止后再清理。
- 完整文字刷新、封面、探针都会重置局刷计数。
- 阈值可在运行时通过串口调整：
  ```json
  {"cmd":"epd_cleanup","every":20}
  ```
- `status` 增加 `partial_updates` 和 `partial_limit` 字段。

实测：

| 场景 | 结果 |
|---|---:|
| 阈值 3，第 3 次局刷后退出菜单 | 自动 `quality` 清理，2344 ms，计数归零 |
| 阈值 3，第 3 次局刷后空闲 | `quality` 清理 2280 ms，计数归零 |
| 阈值 20，20 次局刷后空闲 | `quality` 清理 2280 ms，计数归零 |
| 完整文字刷新 | 重置计数，典型约 1.64 s |
| 快速连续局刷 | 只在停止按键并空闲 1 s 后清理 |

局刷典型耗时 436–470 ms；后台同步期间可出现 1.2–2.2 s 的局刷。完整文字刷新在同步负载下也曾出现 2.3–6.0 s 的波动，P2 参数仍以稳定状态为主。详细数据见 `p2.json` 和 `p2.log`。
