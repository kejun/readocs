# 终端按键与刷新策略

本文件是固件刷新和电池交互等待的维护基线。适用于 PaperDIY / ESP32-S3、ESP-IDF 5.5.5、M5GFX `02107b8` 的 `Panel_EPD`。修改来源页、文章列表、阅读、输入、电源或驱动前，应先核对本文件并运行下面的回归。

## 原始优化与本次退化

2026-10-24 的 [P0/P1/P2 测量及实现记录](../artifacts/display-refresh-2026-10-24/README.md) 已入库。P1 将所有操作整屏 `quality` 改为分级刷新，P2 加入连续局刷 20 次后的质量清理。原测量：选择行局刷 436–477 ms、整屏文字刷新约 1.64 s、质量刷新约 2.28 s；后台负载会增加耗时。这些时间只覆盖 `display` 到 `waitDisplay`，物理按键延迟还包含释放去抖、绘制、启动和缓存读取。

0.2.3 仍包含局刷代码。电池模式无操作 1 秒即深睡，普通 RAM、PSRAM、分页及驱动旧帧状态随之丢失；下一次按键从启动流程重新进入并整页绘制。USB 快速局刷不能代表电池体验。0.2.4 修正交互等待，并将文章列表的刷新依据限制为当前屏幕可见内容。

## 模式与范围

| 操作 | 刷新策略 | 保留条件 |
|---|---|---|
| 来源页、菜单、同屏文章列表移动选择 | `epd_fast`；只重画旧/新选中行，提交两行包围矩形 | 当前界面、可见内容及列表分屏未变 |
| 同一正文翻页 | `epd_fast`；`(0,63,540,897)`，保留标题和分隔线 | 来源、文档、快照、标题、字号、字体修订号、页数及旧帧有效 |
| 当前选择/正文页没有变化 | 跳过绘制和屏幕提交 | 质量清理未到期 |
| 屏外目录项变更 | 当前文章列表跳过刷新 | 总数、可见行及标题未变 |
| 已缓存正文仅 hash 改变 | 文章列表跳过刷新 | 可见标题、身份及“未下载”标记未变 |
| 界面切换、列表换屏、可见内容/字体/布局变化、旧帧未知 | 整屏 `epd_text`，重建基准 | 不能沿用上一界面的选择行缓存 |
| 残影清理或已记录的上次刷新中断 | 整屏 `epd_quality`，计数归零 | 从完整本地快照恢复 |
| 休眠/关机封面 | 整屏 `epd_quality` | 等待完成后再深睡/断电 |

`fast` 使用 1 位阈值，`text` 和 `quality` 保留灰度；不要将所有界面默认改为 `fastest`。正文翻页允许大区域快速刷新。规划稿中的 40% 面积、累计三屏阈值尚未作为当前算法启用；调整应有独立的残影和耗时测量。

`begin()` 会调用 `fillScreen` 并使全部局刷缓存失效。快速分支应直接绘制目标区域，不能先调用 `begin()`、`fillScreen()` 或绘制范围外的状态/时钟。首次整刷完成后才建立缓存有效标记。

M5GFX `display(x,y,w,h)` 将指定范围与此前累计的脏区合并，再按旋转和偶数像素对齐。它不能缩小此前一次 `fillScreen()` 产生的整屏脏区。验收要同时看模式、绘制调用、脏区和提交矩形；逻辑矩形日志不能代替物理残影和窗口外影响的目视检查。

0.2.5 的 Noto Sans SC 与独立黑白 Emoji 均为原生 16 / 24 / 32 像素、1 位压缩字形，不再将 24 像素放大成 32 像素。测宽和绘制共用 `ReaderFont` 与完整 Emoji 序列映射；只转换显示串，分页锚点仍按原文码点计数。字体资源一次初始化，二进制映射自应用 Flash，交互窗口保留索引与分页状态，不能每字重新打开文件或在快速路径重载字库。字体修订号变化时重新分页并按原文块和偏移恢复位置，不复用旧页码或旧帧。字库、授权和重建方法见[资源说明](../firmware/device/fonts/README.md)。

## P2 清理规则

每次实际局刷计数加一，默认阈值 20，可通过 USB `epd_cleanup` 暂时调整。到达阈值后，下一次完整页面绘制使用 `quality`；没有完整切换时，交互停止并空闲 1 秒后清理当前页面。按键未释放、队列未空、联网或配网期间延后清理。

整页文字刷新、质量清理、封面和探针完成后重置计数。内容不变的后台检查不单独更新屏幕，也不因时间经过而周期性闪屏。

## 电池交互等待

| 状态 | 等待行为 |
|---|---|
| 开机、实体键唤醒或实际操作后的 15 秒交互窗口 | 空闲满 1 秒后短暂轻睡，保留 RAM、PSRAM、分页和 EPD 基准，后续按键沿用上表 |
| 短暂轻睡 | GPIO3/4 低电平唤醒，每段最多 25 ms；醒后补轮询无唤醒 IRQ 的 PM1 键，并给 RTOS/看门狗运行机会 |
| 连续 15 秒无操作 | 确认无输入、队列或网络工作后深睡；下次唤醒整页重建基准 |
| 纯定时检查且无人操作 | 不开启额外 15 秒窗口；检查结束、空闲满 1 秒后深睡 |
| 轻睡不可用 | 回退 1 秒空闲深睡，避免 CPU 活跃等待 15 秒 |
| USB 供电 | 保持交互，无用 Wi-Fi 仍关闭 |
| 主动休眠/关机 | 沿用封面和深睡/断电的安全流程 |

轻睡要求波形完成、去抖状态空闲、物理键释放、按键/网络队列为空，且未联网、未配网。共享锁阻止网络任务在轻睡期间开始实际工作，并与 PM1 I2C 互斥。不要用延长 CPU 活跃等待代替轻睡，也不要将深睡重启后未知的旧帧标记为有效。

窗口改善连续操作。长时间阅读后的第一次按键仍需从深睡启动，不能承诺与保留基准时相同的延迟。整板电流和续航尚需测量，轻睡功能通过不等于五天续航通过。

## 回归与实机检查

```sh
.venv/bin/python -m pytest -q tests/test_fonts.py tests/test_reader_layout.py tests/test_reader_refresh.py tests/test_ui_power.py tests/test_input.py tests/test_sleep.py
```

- `test_reader_refresh.py` 执行实际来源、菜单、列表及正文绘制函数，记录模式、`fillScreen`、脏区和提交矩形；覆盖跳过不变画面、屏外变更、换源/字号失效及质量清理。
- `test_fonts.py` 和 `test_reader_layout.py` 使用固定 M5GFX 的实际 BFF 解码与已提交资源，覆盖黑白像素、测宽与绘制步进一致、粗体、缺字、组合 Emoji、各字号整篇分页及度量缓存。不得用另一套伪字体的测量代替。
- `test_ui_power.py` 执行实际轻睡、主循环空闲分支和网络启动屏障，覆盖 1 秒/15 秒边界、纯定时检查、USB、按键/队列/AP/网络拒绝、失败回退及互斥。
- 输入状态机和睡眠保护继续覆盖 25 ms 去抖、1 秒长按、组合键、波形期间积累输入和休眠前检查。按键采样独立于网络和绘制。

烧录只写应用槽，保留设置、目录和正文。`status` 提供 `uptime_ms`、`light_sleeps`、`light_sleep_available` 和 `interaction_window_ms`；0.2.5 另提供 `font_family`、`fonts_ready`、`font_revision`、`emoji_sequences` 和 `font_size`，0.2.6 增加 `font_weight`，当前为 500。

在具有下一项的来源/菜单/同屏列表上，USB 发送一次 `{"cmd":"light_sleep_probe"}` 验证真实轻睡、8 KiB PSRAM 保留及随后一次选择移动仍为快速局刷。探针会自动移到下一项，且仅此显式诊断将结果写入 NVS；普通轻睡循环不写 Flash。ESP32-S3 的原生 USB 时钟在轻睡时停止，主机可能失联，需要重连或受控复位恢复，见[官方说明](https://docs.espressif.com/projects/esp-idf/en/latest/esp32s3/api-guides/usb-serial-jtag-console.html)。恢复后从 `status.light_sleep_probe` 读取已保存的 `complete`、`ok`、`psram_retained`、`fast_refresh_retained` 和局刷前后计数，不能用在线串口是否一直响应判断轻睡成功。

最后拔掉 USB，间隔 2–5 秒连续移动/翻页，并检查长按、组合键、PM1 双击和 15 秒后的唤醒。USB 注入、软件测试和矩形日志各自证明其覆盖范围，不能代替物理按键体验与残影观察。
