## 本轮修复与全量目录实现

截图中的“请输入有效的文档链接或 ID”由未重启的旧 Python 进程返回：静态页面已取消文档输入，旧路由仍校验单篇文档。已同步更新并重启 HTTP 管理端和 HTTPS 设备端；静态页面现在与路由在启动时一同加载，避免进程运行期间出现新表单配旧接口，用用户已填写的凭据完成实际保存，并刷新确认 App ID/Secret 配置保留。未回读或记录 Secret。

飞书改为一个集合源，管理页不再填写文档链接。代理递归发现全部可枚举且可读的 docx，处理空分页、知识库子树、个人文档库和重复引用；代理重启接续任务，逐篇失败退避，部分遍历不误删旧正文。目录与正文任务独立，管理页支持加载更多，设备可直接按文档 ID 获取正文引用。

OAuth 回调有单次 state、浏览器绑定、会话期限及配置版本校验。用户凭据加密保存，刷新并发合并并保留新的 refresh_token。更换账号后重建飞书缓存；授权失效时不改用应用身份继续访问。

设备使用每页 50 条的紧凑目录，去掉旧版的 50/101 条硬编码；进度通过不可变文件与 NVS 指针提交，规避 SPIFFS 不支持覆盖重命名的行为。目录预算为 512 KiB，超过联网预算会接续，超出设备容量会明确提示；代理全量正文不受该目录预算限制。固件只写入应用槽，保留 Wi-Fi、绑定和阅读数据。验证记录位于 `artifacts/all-documents-2026-10-24/`。

大目录实机联调发现片内 RAM 不足导致 `mbedtls_ssl_setup -0x7F00`。TLS 动态缓冲改用板上 PSRAM；保留证书、主机名和时间校验。长文排版过程中定期让出 CPU，避免字体测量使空闲任务长时间得不到调度。


本轮最终实机结果：127 篇临时文档加原有 10 篇，共 137 条目录，缓存正文按配额为 10 篇；软件重启保留 137 条目录。移除临时源后成功恢复原有 10 条目录、5 篇正文。Wi-Fi、设备绑定和串口记录器保留/恢复。见 [目录实机记录](../artifacts/all-documents-2026-10-24/collection.json) 与 [固件记录](../artifacts/all-documents-2026-10-24/firmware.json)。本轮目录内容为协议测试替身，不等于真实飞书账号正文已经授权。

## Cloudflare 隧道接入

代理增加 `--device-prefix /readocs`，只为 `/v1/*` 设备协议添加 `/readocs/v1/*` 路径，保留原有认证、配对码时效、304 前认证和撤销逻辑；管理 API 与静态页面未添加该前缀。本机 HTTPS 已验证，自动测试通过。

指定 Cloudflare 隧道（具体隧道 ID 不写入仓库）。按用户选择，在控制台发布设备专用域名 `<device-host>`，DNS 指向该隧道；仅匹配 `^/v1/.*$`，源站为 `https://127.0.0.1:8766`。cloudflared 使用本机 CA 文件验证源站，SNI 为 `localhost`，未关闭 TLS 验证。原有应用路由保留，本地原配置也已恢复；管理页仍在本机 8765 端口使用。

公网探针通过：未鉴权 401、鉴权清单 200、条件更新 304、正文分块 SHA-256 一致、管理路径 404。Cloudflare 压缩会把 ETag 弱化为 `W/` 形式，代理现按 HTTP 的弱比较规则处理条件更新，并始终先验证设备凭据。

实机首次同步暴露出逐个请求重建 TLS 的开销。固件 0.2.1 在一次网络任务内复用 HTTP 客户端，逐次更新方法、请求体与凭据头；失败或结束时释放连接，在关闭 Wi-Fi 前清除响应回调上下文。目录快照哈希与本地正文校验一致时，跳过重复的正文引用请求。GET 连接失败只在预算允许时额外重试一次，不重放配对或更新 POST；成功同步后清除旧的失败状态。原有证书校验和联网预算配置保留。

已备份并校验当前 4 MiB 应用槽，再仅写入新应用镜像；Wi-Fi、缓存、阅读位置和已通过公网配对取得的设备凭据保留。终端使用 `https://<device-host>` 通过两轮实机同步，最终两轮均一次成功，软件重启后仍可同步，保留 10 条 RSS 目录、5 篇正文和第 1 页阅读位置。旧局域网设备凭据已撤销，保留一个有效绑定，串口记录器已恢复。该轮尚未授权飞书，后续实账号结果见下方。

## 文章日期排序

文章列表改为完整目录按日期倒序后分页，网页与设备协议共用同一顺序。飞书优先使用标题中的有效日期，其次为上游创建时间、更新时间；RSS / Atom 按上游时间排序，统一处理 ISO 8601、RFC 2822 和时区。未知日期排最后，同一日期用文档 ID 保持稳定顺序，不使用本机抓取时间。

飞书目录发现时保存创建和修改时间，正文首次抓取、内容更新及重复检查均保留这些元数据。旧 SQLite 自动增加可空创建时间列，保留已有正文与设置；服务更新前已保存私有数据库备份。实际 449 篇文档已补齐创建时间，管理接口全分页检查通过日期倒序验证，网页与设备端一致性、非法日期回退和旧库迁移测试通过。


## 终端文章列表与同步接续

阅读页长按 B 直接返回文章列表，保留当前文章的选中位置，再次打开恢复阅读页码。开机进入列表，每屏 8 篇、标题最多两行；短按 A 移动、短按 B 打开，长按 A 翻下一屏，长按 B 进入菜单。列表游标使用来源和文档 ID，在后台重排、条目移除和空列表时保持有效；深睡使用 RTC 保留页面与选择。新增 USB 按键事件入口和页面状态，用于验证实际显示完成后的导航行为。

全量目录联调暴露出两个问题：正文抓取进度混入目录版本，导致分页中途失效；大量目录字符串和 cJSON 小对象优先分配片内内存，文件系统创建锁时触发 OOM 重启。目录版本现仅覆盖条目元数据和顺序，新增正文聚合版本触发内容检查；设备断点依据目录标识接续，不因正文完成而从头下载。普通分配的片内优先阈值改为 16 字节，让目录对象优先进入 PSRAM，继续为内核、锁和 DMA 保留 64 KiB 片内内存；未关闭 TLS 验证。

测试覆盖正文变化期间继续分页、正文变化仍触发清单更新、真实目录变化使旧游标失效，以及固件列表游标的翻屏、末尾循环、跨来源身份、重排、删除与空列表边界。37 项测试通过，ESP-IDF 5.5.5 构建完成；实机最终结果见 [终端验证](../artifacts/navigation-2026-10-24/final.json) 和 [导航流程](../artifacts/navigation-2026-10-24/navigation.json)。

断点接续时还会将当前活动索引中已下载的正文引用合并进旧目录进度，按来源和文档 ID 匹配，避免后台接续把按需下载的缓存标记清空。对应边界已加入实际固件逻辑的主机编译测试。

最终实机结果：0.2.2 应用镜像 2835312 字节，SHA-256 `cd392f86b6bc167327082bd0f04ebf7f72707d21a0f0bcf9f1016e769bb41c6c`，仅写入 `0x20000` 应用槽。终端持有 449 条真实飞书目录；按需下载的 21 块正文排成 4 页，翻到第 2 页后返回列表、重新打开及软件重启均恢复第 2 页。列表下一屏和菜单返回已验证，最终停在文章列表首屏。接续与重启后原有两篇正文缓存均保留，期间预取增加至 3 篇；目录和绑定保留。片内空闲约 150 KB，实测最低约 39 KB，未再出现上述内存重启。串口记录器已恢复。导航通过 USB 注入实际按键事件验证，电池深睡和屏幕目视仍需另行验证。

应用槽备份为同目录 `before-app-0.2.1.bin`；恢复时只写回 `0x20000`，不覆盖 NVS、分区表或缓存。整体结果见 [验证摘要](../artifacts/navigation-2026-10-24/release.json)。
