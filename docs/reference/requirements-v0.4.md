### 1.1 三项用户输入的落定结果

| 用户输入 | 落定结论 | 对方案的影响 |

| ②文档在个人空间 | D1 锁定 B：文档留在个人空间不动，由用户把自建应用加为该文档协作者，代理用 tenant_access_token 读取。保留替代路径（§1.3） | 免 OAuth，P-1 只需一次授权动作 |
| ③新增 RSS feed、电源键 + 两个用户键 | RSS 升为独立章节（第 5 章）与 FR-7；按键升为独立章节（第 6 章）与 FR-8；输入方式锁定为物理 3 键（电源键 + KEY1 + KEY2），触摸排除 | P0 范围收窄，BOM 锁定；FR-4 的翻页输入改为按键 |

### 1.2 功耗与续航口径（改写 FR-6、P2 验收）

| 项 | 旧口径（v0.1/v0.2，作废） | 新口径（v0.3 起生效，v0.4 延续） |
|---|---|---|
| 模组 | 需 PSRAM（未锁定） | 锁定带 PSRAM 的模组（容量见 §13.7 第 3 项） |
| 整板深睡电流 | <50 µA | ≤200 µA（测量点：电池正极与整板之间；断开 USB 供电与串口桥；三键未按下；连续 10 min 均值） |
| 模组级 deep sleep 参考值 | 无此条 | ≤50 µA——仅作模组选型的设计目标，**不是本项目验收项**，不得与整板 200 µA 混用；与第 14 章回退条款的关系：只有触发 §14.1「整板 200 µA 不达标」时，才把该量级作为整板回退目标引用，并按实测重定续航 |
| 单次唤醒活跃 | ≤15 s | ≤12 s（P95），平均活跃电流 ≤120 mA |
| 续航验收值 | ≥5 天（按 1000 mAh 标称、深睡 <50 µA、活跃 ≤15 s，未扣可用容量） | ≥5 天（按 800 mAh 可用、深睡 ≤200 µA、活跃 ≤12 s；测算 6.4 天，余量 28%） |

新口径测算：288 次/天 × 12 s × 120 mA ≈ 115 mAh/天；深睡 200 µA × 24 h ≈ 4.8 mAh/天；按键唤醒 10 × 12 s × 120 mA ≈ 4 mAh/天；合计 ≈ 124 mAh/天 → 800 ÷ 124 ≈ 6.4 天，较 5 天下限多 1.4 天（28% 余量）。

旧口径对照：288 × 15 s × 120 mA ≈ 144 mAh/天 + 深睡 50 µA 约 1.2 mAh/天 ≈ 145 mAh/天；按 1000 mAh 标称约 6.9 天，按 800 mAh 可用只有 5.5 天。

「下调」的落点只有三条，缺一不可，故不再出现「新旧都写 ≥5 天」的歧义：①整板深睡由 <50 µA 放宽到 ≤200 µA（深睡日耗 1.2→4.8 mAh/天）；②容量口径由 1000 mAh 标称收紧为 800 mAh 可用；③单次活跃由 ≤15 s 收紧到 ≤12 s（每天抵消约 29 mAh）。三项相抵后口径收紧、验收下限仍 ≥5 天、测算 6.4 天：放水只发生在深睡指标上，续航结论没有被下调。

续航验收工况（缺一不可，写入 P2 与 AC-08）：5 min 轮询、25±3 °C、按键唤醒 ≤10 次/天、不做 OTA、电池标称 1000 mAh 按 800 mAh 可用计、单次唤醒 ≤12 s @ ≤120 mA、不插 USB、串口桥断电。

1 min 档位代价（仅作配网页提示，不作默认值、不参与验收）：≈585 mAh/天 → 800 ÷ 585 ≈ 1.4 天。

回退条款（落点为第 14 章风险与回退）：若后续选改硬件（断电跳线、低静态电流 LDO、裸模组去掉 USB-UART 桥），整板深睡指标回退至 ≤50 µA，续航目标按实测重算，其余章节不变。此处 ≤50 µA 是回退场景的**整板**指标，与本表「模组级参考值」不是同一项，二者不可互换使用。

### 1.3 文档归属与 D1 锁定 B

结论：D1 = B，代理侧持 tenant_access_token 读个人空间 docx。依据是飞书 docx 文档接口的错误码处置说明——tenant_access_token 无权限时返回 403 / 1770032，处置方式是在云文档网页「…」→「…更多」→「添加应用」把应用加为该文档协作者，前置条件是应用已开通云文档 API 权限（来源：https://open.feishu.cn/document/server-docs/docs/docs/docx-v1/document/get ）。该结论来自接口文档说明，未在本项目真实文档上实测，因此保留替代路径：

- 验证动作（P-1 必做）：应用加协作者后，用一次 `curl` 调 `GET /open-apis/docx/v1/documents/:document_id` 取回 title 与 revision_id。
- 若不通过 → 退回 user_access_token：代理托管 OAuth 回调，设备状态页显示重授权短链/二维码，用户人工重新授权。代价：多 5–8 人日；新增 AUTH_EXPIRED 状态、refresh_token 托管与撤销处理；设备端须能渲染二维码（黑白点阵可行）。不通过时的处置同时登记在 §14.1 风险表。

## 2. 统一内容模型

目标：飞书 docx 与 RSS 在代理侧归一化为同一结构，设备端渲染管线零改动。

### 2.1 文档级字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| schema_version | int | 是 | 模型版本，当前 1；设备不识别则拒绝渲染并提示升级 |
| source_id | string | 是 | 稳定唯一标识。docx：`docx:<document_id>`；RSS：`rss:<feed_uuid>`（代理生成，feed URL 变更不换 uuid） |
| source_type | enum | 是 | `docx` 或 `rss` |
| title | string | 是 | docx 取文档标题；RSS 取 feed `<title>` |
| item_title | string | 否 | RSS 条目标题（docx 为空） |
| revision | string | 是 | docx：`revision_id`（整数递增）；RSS：归一化内容哈希（sha256 前 16 位）。用于「版本未变则不刷新」 |
| etag | string | 否 | 上游 HTTP ETag（RSS 用）；docx 为空 |
| last_modified | string | 否 | 上游 Last-Modified（RSS 用） |
| updated_at | ISO8601 | 是 | 内容最后更新时间（RSS 取 pubDate/updated，缺失用 fetched_at） |
| fetched_at | ISO8601 | 是 | 代理抓取时间，用于状态页「上次成功」 |
| pagination | object | 是 | `{cursor, has_more, page_index, page_size, total_blocks}`；cursor 不透明，设备不解析 |
| render_hint | object | 是 | `{default_font_px, line_height_px, margin_px, image_mode, max_blocks_per_page, anchor_hint}` |
| blocks | array | 是 | 见 2.2 |

### 2.2 块字段

| 字段 | 类型 | 说明 |
|---|---|---|
| block_id | string | docx 用原生 block_id；RSS 用 `<item_key>:<seq>`，seq 从 1 递增 |
| type | enum | h1/h2/h3/paragraph/list_ordered/list_unordered/quote/code/divider/image/table |
| text | string | 纯文本，已清洗，不含标签 |
| anchor | object | `{char_start, char_len}`：该块在文档纯文本流中的全局字符偏移，供阅读位置锚定（替代页码书签） |
| level | int | 列表缩进层级（0 起）或标题层级；非列表/标题为空 |
| url | string | 图片或链接地址，已补全为绝对 URL |
| image | object | `{mode: placeholder 或 thumb_1bit, w, h, bytes_ref}`；bytes_ref 指向代理侧图片缓存键 |
| meta | object | `{ordered_start, table_rows, lang}` 等可选渲染提示 |
| hash | string | 块内容哈希（text+type+level），用于块级 diff |

### 2.3 两类源到同一结构的映射

| 目标字段 | 飞书 docx | RSS / Atom |
|---|---|---|
| source_id | `docx:<document_id>` | `rss:<feed_uuid>` |
| revision | `document.revision_id` | feed 级 ETag + 条目级 guid/pubDate/content-hash 合成的 sha256 |
| title | `document.title` | feed `<title>` |
| blocks | heading1/2/3→h1/2/3，text→paragraph，bullet/ordered→list_*，quote_container→quote，code→code，divider→divider，image→image，table→table（MVP 降级为简化文本块） | `content:encoded`/`description` 清洗后按块级标签拆为 paragraph/h*/list/quote/code/image/divider；每 item 至少 1 块 |
| anchor | 由代理按块顺序累加字符长度计算 | 同左（按条目内块顺序累加） |
| render_hint | 固定默认值 | 同左 |

设备端不改渲染管线的原因：设备只消费 `blocks + render_hint + pagination`，不感知来源类型；RSS 的全部差异（XML 解析、编码、去重、清洗、图片降级）在代理侧消化。新增字段只有 `source_type` 与 `item_title`，仅用于页眉与状态页展示。

## 3. 系统架构

```
飞书 docx（个人空间，应用已加协作者）        RSS/Atom 源（多 feed）
        │ tenant_access_token                       │ 条件请求 ETag/Last-Modified
        └──────────────┬───────────────────────────┘
                       ▼
              云函数代理（用户自有账号，0 元档）
   取数 → 归一化为统一内容模型 → 内容哈希/块级 diff → 源快照 + 条目去重缓存
                       │ HTTPS + 设备 token，仅返回变更块（协议 v1）
                       ▼
        ESP32 模组（带 PSRAM，板级规格见第 13 章）
   排版引擎 → 完整 framebuffer → 像素级 diff → 局部刷新窗口
   块缓存/哈希落 LittleFS+NVS；PSRAM 仅作运行时排版缓冲，深睡整体掉电
                       │ SPI
                       ▼
              4 英寸单色墨水屏（局部刷新能力待核实，Q1）
   输入：PWR（开关机/熄屏/复位）+ KEY1 + KEY2（翻页/同步/切源/菜单）
```

刷新三层策略：块级 diff 决定需重排的块范围 → 像素级 diff 取变化像素包围盒作为刷新窗口 → 面积/时间双阈值触发全刷（累计局部刷新面积 ≥ 屏面积 3 倍，或距上次全刷 ≥45 min，或 <10 °C 一律全刷）；启动时校验上次渲染完成标记，不完整则强制全刷。术语口径见第 12 章，板级断电域划分见 §13.3。

## 4. 功能需求（FR）

| 编号 | 名称 | 要求要点 | 验收锚点 |
|---|---|---|---|
| FR-1 | 配网与配置 | SoftAP + 网页配网；SSID/密码/源配置/轮询间隔/时区/按键映射存 NVS；掉电不丢；配置页显式提示 1 min 档位的续航代价 | AC-01 |
| FR-2 | docx 取数 | 代理取文档元信息（title、revision_id）与 blocks；单文档上限 500 块 / 300 KB，超出降级摘要模式；多文档上限 5 篇（P3 开） | AC-02 |
| FR-3 | 增量同步与 diff | revision 未变则不刷新、不写 Flash；变化时拉全量块→代理算块哈希 diff→设备重排→像素级 diff→局部刷新；阅读位置用 block_id + 字符偏移锚点恢复 | AC-03、AC-04 |
| FR-4 | 渲染与阅读 | 元素：h1–h3、段落、有序/无序列表（1 级缩进）、引用、代码块（等宽、超长行截断并标「…」）、分隔线、图片（默认占位框，可选 1-bit 抖动缩略）、表格（降级为简化文本）；中文点阵 16/24 px 两档；自动分页；按键翻页；页眉标题+更新时间，页脚页码+电量+WiFi | AC-05 |
| FR-5 | 状态与异常 | 状态机：空闲/同步中/已是最新（含时间）/无网络/鉴权失败/源失效/抓取失败；失败保留屏上旧内容不白屏；指数退避 1s/4s/9s 三次，退避计数与下次尝试时间落 NVS；按键可强制立即重试 | AC-06、AC-24 |
| FR-6 | 电源管理 | RTC 定时唤醒 → 联网 → 同步 → 深睡；整板深睡 ≤200 µA（口径见 §1.2）；单次唤醒活跃 ≤12 s；按键唤醒立即同步；深睡用 EXT0/EXT1 RTC GPIO 唤醒，非按键外设深睡断电；深睡关闭内部上拉（见 §6.3） | AC-07、AC-08、AC-18 |

## 5. RSS Feed 设计

### 5.1 部署位置与基本决策

设备不直连抓取 RSS，全部由代理抓取并归一化输出块数组。理由：设备端需额外承担 TLS 握手、XML 流式解析、字符集转码、ETag 缓存与唤醒后校时失败导致的证书校验问题；代理侧这些成本接近零，且多设备可共享一次抓取。

### 5.2 feed URL 配置与多 feed 管理

- 最多 8 个 feed；每源字段：`feed_uuid / url / 显示名 / 启用状态 / 抓取周期 / 保留条数 / 图片模式`。
- 增删改在配网网页完成，写 NVS 并同步到代理配置接口；删除源时保留其缓存 7 天后清理。
- 抓取周期可选 10 / 15 / 30 / 60 / 180 min，默认 30 min；10 min 为硬下限。
- 每源独立周期调度；代理侧并发抓取上限 2，其余排队；同源多设备请求做 single-flight 合并。

### 5.3 条件请求

- 每 feed 保存 `etag` 与 `last_modified`，请求带 `If-None-Match` / `If-Modified-Since`。
- 返回 304：不更新 revision、不写缓存、不产生设备同步；设备状态显示「已是最新 · HH:MM · RSS」。
- 返回 200 但内容哈希未变（服务器忽略条件头）：同样视为无变化，走「不写 Flash」路径。

### 5.4 去重与增量

- 条目键归一化：优先进 `<guid>`（去空白）；无 guid 时用 `normalize(link) + | + pubDate`，normalize 为小写 host、去 UTM 与 fragment、去尾斜杠。
- `item_key = sha256(归一化串) 前 16 位`；`item_hash = sha256(标题 + 清洗后正文)`。
- 条目级 diff：`new`（新 item_key）、`updated`（同 key 但 item_hash 或 pubDate 变）、`removed`（本次 feed 中消失，仅从列表移除，不删已读缓存）。
- 设备端只下发 new 与 updated 条目的首块 + 变更块；removed 只更新列表计数。

### 5.5 解析失败与非兼容格式

| 格式 | 支持 | 说明 |
|---|---|---|
| RSS 2.0 | 支持 | 主路径 |
| Atom 1.0 | 支持 | entry/link rel=alternate、content/updated 映射 |
| RDF（RSS 1.0） | 支持 | 只取 items，namespace 前缀按本地名匹配 |
| JSON Feed 1.x | 明确不支持 | 列入后续候选（Q8）；代理检测到 `application/feed+json` 返回 SOURCE_UNSUPPORTED（错误码见 FR-11） |

XML 解析失败处置：先严格模式解析；失败后重试 2 次（换 UA、去不可见字符、修复常见未转义 `&`），仍失败标记 PARSE_ERROR 并保留上次快照，设备显示「抓取失败 · 显示缓存」；连续 3 个周期失败则标 SOURCE_GONE。

### 5.6 字符集转码

检测优先级：BOM → HTTP `Content-Type; charset=` → XML declaration `encoding=` → 默认 UTF-8。若按声明解码后校验失败（U+FFFD 比例 >1%），回退 GB18030（GBK 超集），仍失败回退 Latin-1 并替换非法字符。输出统一 UTF-8。`pubDate` 按 RFC822/RFC3339 双格式尝试，失败用抓取时间。

### 5.7 正文清洗与图片处理

- 标签白名单：p、h1–h6、ul、ol、li、blockquote、pre、code、img、a、br、hr、table/tr/td（降级）。
- 删除 script/style/iframe/object、内联事件属性、`javascript:` 协议；保留纯文本与结构。
- 相对链接用 `<base>` 或 feed URL 补全为绝对地址；协议限 http/https。
- 图片默认 placeholder（固定尺寸占位框 + 文本「[图片]」）；可配 thumb_1bit，最长边 ≤96 px、1-bit 抖动、单条最多 3 张、单次同步图片总量 ≤64 KB，超限自动降级为占位。

### 5.8 缓存与保留策略

- 每 feed 保留最近 50 条元数据 + 最近 20 条正文；正文按 LRU 淘汰；保留时长 ≥7 天。
- 设备端只缓存当前 feed 的当前页 + 相邻 1 页正文，其余按需拉取。
- 写入节流：内容哈希未变时不写 NVS/LittleFS（避免 5 min 轮询造成的 Flash 磨损）。

### 5.9 代理侧超时、重试、限流与降级

| 项 | 参数 |
|---|---|
| 连接超时 / 总超时 | 5 s / 15 s |
| 重试 | 超时与 5xx 退避 1s / 4s / 9s，共 3 次；4xx 不重试（除 429） |
| 限流 | 遵循 `Retry-After`；每 feed 最小间隔 10 min；每代理实例出站并发 ≤2 |
| 大 feed | 响应体 >2 MB 时截断为最近 20 条并记日志 |
| 降级 | 抓取失败一律返回上次快照 + `stale=true`，设备显示上次成功时间，不清屏 |

### 5.10 设备端状态展示

| 场景 | 屏幕 | 日志 |
|---|---|---|
| 无新条目 | 页脚「已是最新 · 12:30 · RSS」 | `rss:source=rss:x not_modified` |
| 有新条目 | 列表页标题前加未读标记，页脚「新增 3 条」 | `rss:new=3 updated=0` |
| 抓取失败（有缓存） | 页脚「抓取失败 · 上次成功 12:30」 | `rss:error=UPSTREAM_TIMEOUT retry=2` |
| 源失效 | 页脚「源不可用：HTTP 404」并跳至下一个启用源 | `rss:error=SOURCE_GONE` |
| 格式不支持 | 页脚「源格式不支持（JSON Feed）」 | `rss:error=SOURCE_UNSUPPORTED` |

RSS 对应验收用例与阈值见 AC-09~AC-14。

## 6. 按键设计

### 6.1 硬件定义（按键 GPIO 的唯一权威表）

| 信号 | 建议 GPIO（ESP32-S3） | RTC 域 | 有效电平 | 上拉 | 备注 |
|---|---|---|---|---|---|
| PWR | GPIO0 | 是（RTC_GPIO，可 EXT0） | 低 | 外部 100 kΩ，深睡关闭内部上拉 | 兼 BOOT strapping，复位瞬间不可按住；长按复位需与 strapping 时序分离 |
| KEY1 | GPIO1 | 是（EXT1 位 0） | 低 | 外部 100 kΩ，深睡关闭内部上拉 | 深睡唤醒源 |
| KEY2 | GPIO2 | 是（EXT1 位 1） | 低 | 外部 100 kΩ，深睡关闭内部上拉 | 深睡唤醒源 |

本表是按键 GPIO 的唯一权威来源，其余章节不得复制或改写上述三行。屏 SPI 控制脚、电池采样脚等新增引脚统一见 §13.5。若最终模组不是 S3，GPIO0/GPIO2 等为 strapping 引脚，须重新分配，本表随之更新（Q6）。对外部上拉 100 kΩ 的硬性约束与电流核算见 §6.3 与 AC-18。

### 6.2 电气与消抖参数

- 消抖：5 ms 周期采样或 GPIO 中断 + 25 ms 定时复核；按下稳定 ≥25 ms 才计一次有效事件；释放抖动 ≤25 ms 合并（可配 20–50 ms）。
- 判定窗：短按 <800 ms；长按 ≥1000 ms 触发（800–1000 ms 为抖动死区）；双击间隔 ≤300 ms，双击判定后不再触发单击。
- 单击延迟：为区分双击，单击动作在释放后 300 ms 执行（翻页场景可配 0 ms 立即执行，代价是牺牲双击识别）。
- 唤醒抑制窗：300 ms，从唤醒中断起算，见 §6.3 与 §6.5。

### 6.3 低功耗、唤醒配置与按键电流核算

- 深睡时非按键外设（屏、SPI、UART 桥）断电，仅保留 RTC IO 唤醒使能。
- 内部上拉/下拉在深睡一律关闭（ESP32 内部上拉约 45 kΩ，若三键保持内部上拉，3 × 3.3 V / 45 kΩ ≈ 220 µA，直接吃光整板 200 µA 预算）。因此只允许外部 100 kΩ 上拉。
- 电流核算（深睡、三键均未按下、低有效接地）：上拉网络在键未按下时无持续电流通路；真正的静态项是 3 路 RTC GPIO 输入漏电，按 datasheet 量级 ≤1 µA/键（典型 0.1 µA），合计 ≤3 µA；上拉网络自身漏电取 ≤5 µA 余量；RTC IO 保持与唤醒逻辑计入整板预算，不重复计入本项。故按键相关深睡电流 ≤8 µA，预算口径取 ≤20 µA（含测量误差与器件离散），与整板 ≤200 µA 相容。
- 按键按下瞬时电流：3.3 V / 100 kΩ ≈ 33 µA/键；即便每天按 10 次、每次 2 s，折算日均 <0.001 mAh，可忽略。
- 若改用 10 kΩ 上拉：单键按下 330 µA，三键同时按下近 1 mA，会拉高按键期间瞬时功耗并加重上拉网络漏电，不采用。
- 唤醒源：KEY1/KEY2 走 EXT1 + ANY_LOW（任一键按下即唤醒）；PWR 走 EXT0（单键低电平）或并入 EXT1。
- 唤醒后行为可配：`wake_action = render_then_sync`（默认，先渲染缓存帧，目标 ≤800 ms 亮屏，再发起同步）或 `sync_then_render`。
- 唤醒抑制窗 300 ms：从唤醒中断起算，窗口内不采样按键、不产生单键或组合键事件（上拉稳定 + 防误触 + 组合键抑制三件事共用这一窗口）；窗口结束后才恢复采样与组合键计时。

### 6.4 功能映射

| 键 | 短按 | 长按（≥1 s） | 双击 |
|---|---|---|---|
| PWR | 深睡中：开机并唤醒；运行中：熄屏/亮屏切换（画面保持，不刷新） | 运行中：强制复位重启固件 | 不定义 |
| KEY1 | 下一页 / 下滚一屏 | 立即同步（穿透退避） | 切换内容源（docx 与各 RSS 源循环） |
| KEY2 | 上一页 / 上滚一屏 | 打开/关闭菜单（菜单内＝确认） | 返回 / 取消 |

硬件级断电（PWR 长按 8 s 硬断电）需要电源锁存电路支持，当前未核实，见第 11 章 Q11；本版不把该动作定义为功能，也不列入 §6.6 用例表与验收范围。

### 6.5 防误触与组合键

- 单键事件必须满足：按下稳定 ≥25 ms 且释放后无二次抖动。
- 唤醒抑制窗 300 ms 内不存在任何按键事件；组合键的 2 s 计时从抑制窗结束后重新起算（这是 §6.5 与 K14 的唯一判定口径）。
- 组合键 KEY1+KEY2 同时按住 ≥2 s：进入配网模式（SoftAP），需屏幕二次确认（KEY2 短按＝确认，KEY1＝取消），防误入。
- 组合键优先级高于单键：一旦识别为组合键，本次按键周期内不再产生单键事件；若两键在同一次按下中先后释放且总按住时间 <2 s，则两键事件均丢弃。
- 同步/渲染进行中，仅 PWR 长按复位有效，其余按键事件入队，同步结束后按序执行（队列深度 4，溢出丢弃最旧）。

| 术语 | 口径 |
|---|---|
| 整板深睡电流 | 电池正极与整板之间测得的稳态电流，条件：断开 USB 供电与串口桥、三键未按下、连续 10 min 均值。唯一验收值 ≤200 µA（AC-07） |

| 块级 diff | 以 block_id + 块内容哈希比较，决定哪些块需要重新排版 |

| 残影 | 电泳屏因未全刷而残留的上一帧灰度痕迹；不是 OLED 式烧屏，长期静态画面无累积损伤 |

| 常电域 / 可断域 | 常电域＝深睡仍需供电的部分（MCU RTC 域、按键上拉）；可断域＝深睡必须断电的部分（屏、SPI、USB-UART 桥、传感器、电池采样分压） |

| 占位框 / 1-bit 抖动缩略 | 占位框＝固定尺寸空框 + 「[图片]」文本；1-bit 抖动＝黑白两值近似灰度，最长边 ≤96 px |

| PSRAM | 外部伪静态 RAM，仅作运行时排版缓冲；深睡整体掉电，不保存现场 |
| 500 块 / 300 KB 上限 | 单文档块数与代理侧全量拉取的硬边界，超出降级为摘要渲染 |

| 供电 | 单节锂电 + 充电 IC + 保护；整板深睡 ≤200 µA | 已锁定指标 |
| 测量 | 电池电压 ADC 采样，采样电路需 MOS 开关，深睡零漏电；板面预留 TP1/TP2 | 已锁定 |
| 调试 | 串口桥必须可断电（跳线/割线/使能脚任一） | 已锁定为硬约束 |

### 13.3 开发板选型 5 条硬约束（不满足即换板，不接受降指标）

1. 带 PSRAM，且 PSRAM 供电域在深睡时整体掉电（不额外维持供电）。
2. USB-UART 桥必须能被切断供电：跳线、割线或使能脚任一方式。常见 CH340/CP2102 类桥常供电时静态电流在数百 µA 到 mA 级，只要它一直带电，整板 200 µA 指标就不可能达标。这是 AC-07 能否通过的第一前提。
3. LDO 静态电流目标 ≤10 µA；只能靠读器件手册确认，候选型号待选型核实（Q13），本版不作结论。
4. 按键所用的 3 个 GPIO 必须落在 RTC 域，可作 EXT0/EXT1 唤醒源，并避开 strapping 引脚与 USB 引脚。
5. 屏 FPC 与背板走线支持 SPI 时钟按屏型号上限运行；屏供电在深睡可断（墨水屏断电保持画面）。

这 5 条与 FR-12 一一对应，验收落点 AC-27（第 2 条）、AC-28（电池采样）、AC-29（第 5 条）。

### 13.4 整板深睡电流预算表（分项相加 ≤200 µA）

| 分项 | 预算 | 说明 |
|---|---|---|
| MCU 模组 deep sleep | ≤50 µA | 选型设计目标，非验收项（与 §1.2 同口径）；具体以模组手册为准，未核实 |
| PSRAM | 0 | 深睡整体掉电 |
| LDO 静态 | ≤10 µA | 选型硬约束（§13.3 第 3 条） |
| 墨水屏 | 0 | 断电保持画面，无需维持供电 |
| USB-UART 桥 | 0 | 必须断电，否则本项直接击穿预算（§13.3 第 2 条、AC-27） |
| 按键上拉网络 + 3 路 GPIO 漏电 | ≤20 µA | 对应 AC-18：外部 100 kΩ、关闭内部上拉 |
| 电池采样分压 + 充电 IC 静态 | ≤10 µA | 分压用 MOS 开关，不用时常通（AC-28） |
| 合计 | ≤90 µA | 上述分项直接相加 |
| 余量 | ≥110 µA | 覆盖温漂、器件离散与测量误差，使合计 ≤200 µA |

与回退条款的引用关系：本表的整板目标 ≤200 µA 是 AC-07 的判据；若实测超限，按第 14 章「整板 200 µA 不达标」行启用回退（改硬件或按实测重定目标，届时以 ≤50 µA 量级作为整板参考）。表中「模组级 ≤50 µA」只是选型设计目标，不是验收值，也不作为回退后的整板目标直接套用。

### 13.6 新增功能需求 FR-12 与验收项

FR-12 板级硬件与供电：开发板须满足 §13.3 的 5 条硬约束；断电域划分为常电域（MCU RTC + 按键上拉）与可断域（屏、SPI、USB-UART 桥、传感器、采样分压）；板面预留 TP1（电池正极）与 TP2（整板 VCC）供深睡电流测量；电池采样电路深睡零漏电。验收锚点 AC-27、AC-28、AC-29，定义见 §10.1。
