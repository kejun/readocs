# 终端检查更新

## 用户入口与顺序（0.2.9）

「菜单 → 检查更新」和内容来源页长按 A 共用同一入口：立即显示排队状态，菜单入口回到来源列表；随后连接已保存的 Wi-Fi，先通知代理检查**全部已配置来源**（飞书及每个 RSS / Atom），再下载目录和当前可用的正文。处于错误退避中的来源也必须收到这次手动更新请求。

来源页底部显示来源更新进度、飞书正文检查数量、终端下载接续、成功或失败。飞书数量表示本轮上游已处理正文数，不能当作 SD 已缓存数量；缓存数量另见 USB `status.cached_documents`。网络任务可在后台运行，仍能浏览缓存。文章列表长按 A 保留原有的下一屏功能。

## 接续和完成条件

1. 终端在目录/SD 下载之前 `POST /v1/refresh`，202 返回 `refresh_id` 和原有 `job_ids`。0.2.10 起，配置局域网加速地址时，先用只读 `GET /v1/status` 选择可达线路：局域网 GET 失败后沿用重建连接及公网回退，选定线路后只发一次 POST。没有局域网配置或已有持久化请求 ID 时不增加此探测。不得将 POST 放到目录/SD 下载末尾，也不得因目录分批提前返回而跳过。POST 丢失响应时仍不自动重放；下次人工操作可重新请求，代理会合并尚在进行的同一轮全源更新。
2. 终端将请求 ID 写入设置 NVS，再 `GET /v1/status?refresh_id=...` 和 `/v1/sync`。深睡或重启后继续查询原请求，后续批次不会再次把所有飞书正文重置为待检查。
3. 代理把目标来源及配置代次、开始时间和最终结果持久化。队列暂时为空不等于完成：飞书目录扫描、`due=0` 正文及未满六次的临时正文错误仍算进行中。源级临时错误沿用退避，未满六次继续等待；永久错误、授权失效和重试耗尽显示部分失败，并保留旧内容。整轮等待上限两小时；超时、配置变更或请求被替换会提示重新检查。
4. 终端每批 SD 同步最多 120 秒，实际下载有进展时接续下一批；仅上游仍在处理时，停止 Wi-Fi，正常约 60 秒后再检查。网络失败沿用退避，不通过 CPU 空转或持续开 Wi-Fi 等待。完成时清除 NVS 请求 ID；最后一次清单为 304 也要清除旧的上游 pending 标记。
5. 状态接口的 `refresh.state` 为 `running / completed / partial / expired / superseded`，同时保留旧接口字段。只有整轮上游结束且本地同步完成时显示「已同步」；部分失败不可显示为成功。失败结果冻结，后续周期任务不能重新打开已结束的请求。

入口共用 30 秒去重，避免按键、菜单和 USB 重复入队；队列已满必须反馈，并允许立即重试。成功与失败调度使用显式任务结果，不能依赖「已同步」等中文提示的字面值。

冷启动的后台 SD 校验须在文件之间检查人工检查队列；有人工请求时安全让出，由队列优先执行全源更新，再继续验证缓存。不能让刚提交的检查等整库校验结束才通知上游。

## 最新文档优先（2026-10-29）

代理的正文检查队列与阅读列表的显示顺序分开维护。只选择已到重试时间的条目；到期失败文档先恢复，其余按已发现的上游**最后修改时间倒序**检查。缺失或无效时依次使用创建时间、标题中的日期，无日期的条目最后处理；相同日期按到期时间、文档 ID 稳定排序。旧文章今天被修改也应优先，不能先按 ID 或 `due=0` 的字面大小遍历全库。普通周期任务和人工全源检查共用此规则。

目录发现仍逐页持久化，与正文检查交替执行；尚未发现的文档无法提前排队，因此这里的优先级针对当前已发现条目。终端阅读列表沿用原有标题日期 / 创建时间排序，代理每篇检查成功就发布可用快照。终端按现有接续周期获取已发布内容，不需要等待整轮 463 篇检查完成；已有同版本且校验通过的 SD 正文跳过下载。空间允许时，其余旧文档仍会全部接续，不因“最新优先”缩减离线范围。

进度表示逐篇上游检查，包含没有变化的文档。当前每篇串行读取文档元数据、全部正文块、再次读取元数据以校验修订号；正常一次至少三个上游请求，工作调度另有约一秒间隔。人工全库检查会比只下载新增快照耗时更长。`feishu_document_checked` 记录每篇耗时和快照是否变化，失败和限流仍沿用有界退避；不能为提高计数而取消修订围栏或提前报告全源完成。终端仅等待上游时约每分钟获取状态，屏幕计数并非实时逐篇变化。

`tests/test_sync_priority.py` 使用实际工作任务覆盖普通 / 手动检查、最近修改优先于标题或创建时间、未知 / 非法时间回退、到期失败优先、未到重试期限不提前执行，以及阅读顺序保持原规则；飞书恢复、日期和全源接续回归须同时通过。

## USB、Wi-Fi 与电池检查

文档始终通过 Wi-Fi 的 HTTPS 请求传输。USB 仅承担供电、配置和诊断，不是文档传输通道；Readocs 配网热点只用于保存目标 Wi-Fi，不能替代目标网络和代理连接。

正常完成后，USB 供电约每 5 分钟拉取代理已有内容；电池使用已保存的检查周期（默认 1 小时），通过深睡定时器唤醒。代理飞书每 3 小时检查上游是另一层周期，不等于终端下载周期。人工检查尚未结束时约 60 秒接续；SD 本批已有下载进展时继续下一批。每批结束关闭 Wi-Fi，因此空闲时 `connected=false` 不表示配网失败。

0.2.10 修正过期检查时间：交互、清屏等使检查时间已到或已过时，深睡定时器最多等待 30 秒，不能重新等待整个检查周期。15 秒交互窗口、局刷缓存和失败退避保持原策略。真正断电关机后不会定时同步，须先开机；普通深睡仍保留定时唤醒。

## 显示与维护约束

来源页状态仅在人工检查或恢复尚未完成的人工请求后展示；普通后台检查不主动新增状态行。状态单独变化使用 `epd_fast` 的 `(24,824,492,40)` 矩形，不调用 `begin()` / `fillScreen()`，状态文字截断后的可见像素不变则跳过。选择行移动继续沿用原来的局刷；整页首次绘制和质量清理沿用[刷新策略](device-refresh.md)。不要将状态串拼进整页失效签名。

代理先部署新接口，再安装 0.2.9 固件。旧代理缺少请求进度时，终端应明确提示更新代理，不能把旧缓存当作本轮全源检查成功。

回归使用实际函数：`test_device_refresh.py` 覆盖认证、限流、全部来源、空队列、持久化、合并、临时恢复、永久失败和过期；`test_sd_sync.py` 覆盖 POST 在清单之前、目录提前返回、无重复 POST、304 收尾及失败保留；`test_source_actions.py` 与 `test_download_resume.py` 覆盖两个入口和绘制触发；`test_reader_refresh.py` 检查底部矩形、旧像素保留、相同状态跳过及来源选择局刷。同步修改仍须运行存储、下载、传输、输入和电源全量回归及 SDK 构建。
